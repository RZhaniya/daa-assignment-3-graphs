## 1. Цель работы

Реализуйте графовые алгоритмы для кабельных соединений, зависимостей подготовительных работ и маршрутов доставки. Каждый запрос содержит независимый граф.

Реализуйте `dsu`, `kruskal`, `prim`, `scc`, `topo` и `dag` указанными ниже методами. Разрешены стандартные коллекции, сортировка, очереди с приоритетом и готовые JSON-адаптеры; графовые алгоритмы реализуйте самостоятельно.

## 2. Требования к программе

Выберите один язык. Сохраните готовый интерфейс UTF-8 JSON Lines: один запрос на входную строку и один JSON-объект результата на выходную. В стандартный вывод отправляйте только результаты. Процесс может получить несколько запросов; сбрасывайте состояние алгоритма для каждого запроса.

Вершины нумеруются от `0` до `n-1`. ID рёбер — исходные позиции в `edges`, начиная с нуля; сохраняйте их при сортировке и построении списков смежности. Целочисленные входы и выходы, включая метки SCC, должны помещаться в знаковый 64-битный тип. Не допускайте переполнения при вычислении стоимостей и расстояний; целые числа Python подходят. Недостижимое расстояние обозначайте JSON-значением `null`.

Все границы включительные. Обозначения: `n` — число вершин, `m` — число рёбер, `q` — число операций объединения.

| Метод | Вершины | Рёбра или операции | Веса рёбер |
|---|---|---|---|
| `dsu` | `0 <= n <= 100000` | `0 <= q <= 250000` | Не используются |
| `kruskal`, `prim` | `0 <= n <= 100000` | `0 <= m <= 250000` | `-1000000000 <= w <= 1000000000` |
| `scc`, `topo` | `0 <= n <= 100000` | `0 <= m <= 250000` | Не используются |
| `dag` | `1 <= n <= 100000` | `0 <= m <= 250000` | `-1000000000 <= w <= 1000000000` |

Концы рёбер и аргументы операций являются допустимыми номерами вершин. При `n=0` список рёбер или операций пуст. В запросе DAG источник удовлетворяет условию `0 <= source < n`. Входные данные соответствуют этим требованиям; некорректный JSON и выход за границы не оцениваются. Регистр имён полей и задач имеет значение.

Обрабатывайте глубокие графы без переполнения стека вызовов. Оценки памяти включают возвращаемый результат. Порядок выходных полей не фиксирован; при неоднозначности принимается любой корректный ответ.

Готовый адаптер отвечает на `{"task":"ping"}` результатом `{"status":"ready"}` для проверки запуска. Сохраните это поведение.

## 3. Связность: система непересекающихся множеств

Кабели между площадками добавляются по одному. Реализуйте `find` и `union` со сжатием путей и объединением по размеру или рангу. Изначально каждая вершина образует отдельную компоненту.

**Вход:** `task="dsu"`, `n` и массив `operations` из пар `[u,v]`, задающих неориентированные соединения.

**Выход:** массив `states`, содержащий пару `[components,largest]` после каждой операции. Здесь `components` — число компонент связности, `largest` — число вершин в наибольшей компоненте. Начальное состояние до первой операции в ответ не включайте.

Повторное объединение и объединение вершины с собой допустимы и не должны менять разбиение. Изначально `largest=1` при `n>0`; при `n=0` значение `largest=0`, результат `states=[]`. Если используете объединение по рангу, отдельно храните размеры компонент: ранг не равен размеру.

Пример входа:

```json
{"task":"dsu","n":4,"operations":[[0,1],[1,2],[0,2],[3,3]]}
```

Выход:

```json
{"states":[[3,2],[2,3],[2,3],[2,3]]}
```

**Сложность:** `O(n + q α(n))` амортизированного времени и `O(n+q)` памяти с учётом состояний. `α(n)` — обратная функция Аккермана; оценка `O((n+q) α(n))` также является допустимой верхней границей.

## 4. Кабельная сеть минимальной стоимости: Краскал и Прим

Найдите минимальный остовный лес неориентированного взвешенного графа. Соедините вершины каждой компоненты с минимальной суммарной стоимостью без циклов. Изолированные вершины учитывайте как отдельные компоненты.

Подготовьте две отдельные реализации:

- `kruskal`: отсортируйте рёбра по весу и используйте DSU. Принимайте ребро только при `find(u) != find(v)`.
- `prim`: используйте списки смежности и очередь с приоритетом. После завершения одной компоненты начинайте с непосещённой вершины, пока не будут обработаны все вершины.

**Вход:** `task="kruskal"` или `task="prim"`, `n` и массив `edges` из троек `[u,v,weight]`.

**Выход:** `cost`, `edge_ids` и `components`. Верните сумму весов выбранных рёбер, их исходные ID и число компонент связности входного графа.

Допускаются параллельные рёбра, равные и отрицательные веса, петли. Не выбирайте петли и не повторяйте ID ребра. При `c` компонентах остовный лес содержит ровно `n-c` рёбер. При `n=0` верните `cost=0`, `edge_ids=[]`, `components=0`. Принимаются разные оптимальные леса и любой порядок выбранных ID. Краскал и Прим должны давать одинаковую минимальную стоимость и число компонент; выбранные ID могут различаться.

Пример входа:

```json
{"task":"kruskal","n":4,"edges":[[0,1,4],[1,2,2],[0,2,3]]}
```

Один из допустимых ответов:

```json
{"cost":5,"edge_ids":[1,2],"components":2}
```

Вершина `3` изолирована. Замена имени задачи на `prim` передаёт тот же граф второй реализации.

**Сложность:** Краскал — `O(n + m log(m+1))` времени. Прим — `O(n + m log(m+1))` с ленивой очередью или `O((n+m) log(n+1))` с индексированной очередью. Память обоих методов — `O(n+m)`.

## 5. Циклические зависимости: компоненты сильной связности

Ребро `u -> v` задаёт ориентированную зависимость. Найдите максимальные группы взаимно достижимых вершин **алгоритмом Косарайю**: два обхода DFS, транспонированный граф и убывающий порядок завершения первого обхода при выборе корней второго. Можно начинать с любого из двух графов, если второй обход использует его транспонированную версию.

**Вход:** `task="scc"`, `n` и ориентированные `edges` вида `[u,v]`.

**Выход:** массив `component` с одной неотрицательной целочисленной меткой для каждой вершины и массив пар `condensation` вида `[from_label,to_label]`. Одинаковые метки должны обозначать ровно одну SCC. Метки не обязаны быть последовательными или следовать определённому порядку.

Каждую направленную пару между разными компонентами включите ровно один раз. Внутренние рёбра и повторные пары исключите. Изолированные вершины образуют отдельные SCC. Повторяющиеся входные рёбра и петли допустимы. При `n=0` оба выходных массива пусты. Порядок рёбер конденсации не фиксирован.

Пример входа:

```json
{"task":"scc","n":4,"edges":[[0,1],[1,0],[1,2],[0,2],[2,3]]}
```

Один из допустимых ответов:

```json
{"component":[5,5,7,9],"condensation":[[5,7],[7,9]]}
```

**Сложность:** `O(n+m)` ожидаемого времени при удалении повторных пар с помощью хеш-множества и `O(n+m)` памяти.

## 6. Порядок подготовительных работ: топологическая сортировка через DFS

Определите, можно ли упорядочить все подготовительные работы. Ребро `u -> v` означает, что работа `u` должна завершиться до начала `v`.

Реализуйте DFS с тремя состояниями: непосещённая, активная и завершённая вершина. Ребро в активную вершину указывает на направленный цикл. Само по себе ребро в завершённую вершину не указывает на цикл. Проверьте все компоненты и при отсутствии циклов разверните порядок завершения DFS.

**Вход:** `task="topo"`, `n` и ориентированные `edges` вида `[u,v]`. Повторные рёбра и петли допустимы.

**Выход:** логическое поле `acyclic` и массив `order`. Для ациклического графа верните `acyclic=true` и все вершины ровно по одному разу так, чтобы каждое ребро вело вперёд по порядку. При любом направленном цикле верните `acyclic=false` и `order=[]`. Петля является циклом. При `n=0` верните `acyclic=true` и `order=[]`.

Пример входа:

```json
{"task":"topo","n":4,"edges":[[0,2],[1,2],[2,3]]}
```

Один из допустимых ответов:

```json
{"acyclic":true,"order":[1,0,2,3]}
```

**Сложность:** `O(n+m)` времени и памяти. Явный стек DFS должен сохранять позицию продолжения каждого приостановленного обхода, чтобы не просматривать соседей многократно с начала.

## 7. Маршруты доставки: кратчайшие пути в DAG

Найдите кратчайшие пути из заданного источника в ориентированном ациклическом графе. Отрицательные веса допустимы. Проверьте весь граф на циклы, затем релаксируйте исходящие рёбра достижимых вершин в топологическом порядке.

**Вход:** `task="dag"`, `n`, ориентированные `edges` вида `[u,v,weight]` и `source`.

**Выход:** `acyclic`, `distance` и `parent_edge`.

- Если в любой компоненте есть направленный цикл, включая недостижимый из источника, верните `acyclic=false`, `distance=[]`, `parent_edge=[]`.
- Иначе верните `acyclic=true` и массивы длины `n`.
- Для источника: `distance=0`, `parent_edge=-1`.
- Для недостижимой вершины: `distance=null`, `parent_edge=-1`.
- Для каждой другой вершины: кратчайшее расстояние и исходный ID входящего ребра кратчайшего пути из источника. Ребро должно заканчиваться в этой вершине; последовательность родительских рёбер должна приводить к источнику.

Не выполняйте релаксацию из недостижимой вершины. Не обозначайте недостижимое расстояние числом `-1`: это может быть корректная конечная стоимость. `parent_edge` хранит ID ребра, а не номер вершины-предшественника. При параллельных рёбрах и равных кратчайших путях принимаются разные корректные массивы родителей. Петля делает граф циклическим.

Пример входа:

```json
{"task":"dag","n":5,"source":0,"edges":[[0,1,3],[0,2,8],[1,2,-7],[2,3,4]]}
```

Один из допустимых ответов:

```json
{"acyclic":true,"distance":[0,3,-4,0,null],"parent_edge":[-1,0,2,3,-1]}
```

Добавьте вспомогательную функцию восстановления последовательности вершин по выбранным ID `parent_edge`. Достижимый маршрут должен идти от источника к цели; маршрут к источнику — `[source]`. Выберите и опишите результат для недостижимой цели, например пустой список или значение null. Этот выбор относится только к вспомогательной функции; в JSON-массиве `distance` недостижимость по-прежнему обозначается `null`. Вызовите функцию в своих тестах для достижимой цели, источника и недостижимой цели. Также проверьте равные пути или параллельные рёбра. В примере маршрут к вершине `3` — `[0,1,2,3]`, стоимость — `0`.

Вспомогательная функция не является отдельной задачей JSON. **Сложность:** `O(n+m)` времени и памяти для кратчайших путей в DAG; `O(L)` времени и памяти результата для восстановления маршрута из `L` вершин.

**Public checks показывают только прохождение тестов. Они не рассчитывают итоговый балл и не передают оценки в Moodle.** Ваша оценка за практику определяется по рубрике из 18 групп ниже; отдельный инструмент оценивания не включён в этот репозиторий.

| Метод | Core | Граничные случаи | Witness | Scale | Всего |
|---|---:|---:|---:|---:|---:|
| DSU | 4 | 2 | — | 2 | 8 |
| Краскал | 4 | — | 2 | 1 | 7 |
| Прим | 4 | — | 2 | 1 | 7 |
| Косарайю SCC | 5 | — | 3 | 2 | 10 |
| Топологическая сортировка DFS | 4 | 2 | — | 2 | 8 |
| Кратчайшие пути в DAG | 5 | — | 3 | 2 | 10 |
| **Итого** | **26** | **4** | **10** | **10** | **50** |

Core проверяет результаты и оптимальные значения; граничные случаи — особые входы; Witness — рёбра леса, конденсацию или родительские пути; Scale — большие входы. Прочерк означает отсутствие группы данного типа. Каждая из 18 групп даёт свой максимум, умноженный на долю пройденных проверок, с округлением half-up до 0,01. Сумма баллов — не более 50; другие допустимые оптимумы принимаются.

Заданные алгоритмы, вспомогательная функция, анализ, собственные тесты и сравнение времени обязательны как учебная работа без отдельных ручных баллов и произвольных вычетов. Публичные тесты не заменяют требования к полному диапазону входов и отдельное оценивание.

[Тренировочный вариант: 20 вопросов с ответами и объяснениями (на английском)](docs/A3_Defence_Practice_EN.pdf). Сначала решите его за 20 минут, затем проверьте ответы.

[Квиз по защите Assignment 3](https://lms.astanait.edu.kz/mod/quiz/view.php?id=93521) проходит на английском языке: 20 вопросов за 20 минут, одна попытка. В нём 15 вопросов с одним правильным ответом и 5 вопросов с несколькими правильными ответами: отметьте все подходящие варианты. Максимум за каждый вопрос — 1 первичный балл. В одиночном выборе верный ответ даёт 1, неверный — 0. В вопросах с двумя верными вариантами каждая верная отметка даёт 0,50, а каждая неверная вычитает 0,25. При трёх верных вариантах используются веса +1/3 и −1/6. Суммируются веса отмеченных вариантов; минимум за вопрос — 0. Пропуск даёт 0. Выбор всех вариантов даёт соответственно 0,25 или примерно 0,67. Для полного балла нужно отметить все верные варианты и ни одного неверного. Оценка за квиз: `raw / 20 × 50`, максимум 50 баллов. Правила курса, включая исправление ошибок оценивания и академическую добросовестность, определяются силлабусом.
